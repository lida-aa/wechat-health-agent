# WeChat Health Agent 功能清单

> 当前版本：健康管理单 Agent。本文只描述当前代码，不包含多功能机器人阶段的历史能力。

## 1. 渠道与交互

| 能力 | 当前状态 | 说明 |
| --- | --- | --- |
| 微信文本消息 | 已实现 | 进入 Agent 编排与健康工具调用流程 |
| 微信语音输入 | 已实现 | 接收 SDK 转写文本；不提供语音合成回复 |
| 健康图片 | 已实现 | 用于餐食或体检报告识别，临时文件处理后删除 |
| 多轮对话 | 已实现 | 对话历史保存到 MySQL，并限制上下文规模 |
| 确认 / 修改 / 取消 | 已实现 | 用户可用自然语言处理待确认的健康操作 |
| 任意文件助手 | 已移除 | 不再处理通用文件翻译、摘要或导出 |

## 2. Agent 工具

### 2.1 只读工具

只读工具可以自动执行，但仍需遵守医疗安全提示和用户隔离。

| 工具 | 用途 |
| --- | --- |
| `health_overview` | 查看个人健康档案概览 |
| `find_pharmacy` | 查询附近药店 |
| `symptom_screening` | 症状风险初筛和就医分流，不做诊断 |
| `interpret_health_report` | 解读当前提供的体检报告文字 |
| `interpret_latest_health_report` | 解读档案中最近一次报告 |
| `open_health_exam` | 返回配置的体检预约入口 |
| `daily_health_briefing` | 生成健康陪伴简报 |
| `today_diet_summary` | 查看当天饮食与热量汇总 |
| `list_reminders` | 查看当前提醒 |
| `food_nutrition` | 查询食物营养信息 |
| `health_tip` | 查询健康科普提示 |
| `body_fat_rate` | 计算体脂率和身材指标 |

### 2.2 需要用户确认的工具

这些工具只创建草稿。只有真实用户确认后，后端才会领取草稿并写入数据。

| 工具 | 写入内容 |
| --- | --- |
| `record_profile_fact` | 基础信息、生活习惯、过敏史、既往史等 |
| `add_medication` | 用药计划及关联提醒 |
| `record_vital` | 血压、血糖、体重、体温等指标 |
| `log_medication` | 服药打卡 |
| `save_health_report` | 体检报告归档 |
| `create_health_plan` | 饮食和运动计划 |
| `analyze_meal` | 餐食分析与饮食记录 |
| `create_reminder` / `schedule_health_briefing` | 每日健康提醒 |
| `cancel_reminder` | 取消已有提醒 |

### 2.3 工具安全

- `HealthToolPolicy` 使用显式白名单和风险等级；未登记工具不能注册或执行。
- `userId` 不进入模型工具参数，由微信会话通过 `@CurrentUserId` 注入。
- 写工具必须带 `@CreatesHealthActionDraft`，避免新增工具绕过 HITL。
- 模型提出 Tool Call 不等于授权执行，最终权限和状态迁移由后端控制。

## 3. Human-in-the-loop

支持的流程：

```text
创建草稿 → 等待确认
            ├─ 修改允许字段 → 继续等待确认
            ├─ 取消 → CANCELLED
            ├─ 超时 → EXPIRED
            └─ 确认 → EXECUTING → COMPLETED / FAILED
```

当前保护包括：用户隔离、TTL、Redis 恢复、原子领取和重复确认幂等。

## 4. 数据与提醒

| 能力 | 实现 |
| --- | --- |
| 健康档案 | MySQL `health_record` JSON 聚合文档，带版本字段 |
| 旧数据兼容 | 数据库无记录时一次性导入旧 JSON；之后只写 MySQL |
| 健康提醒 | MySQL `health_reminder` 持久化 |
| 调度可靠性 | 到期扫描、原子抢占、每日去重、重试退避和 `DEAD` 状态 |
| 待确认状态 | Redis 优先，故障时退化为进程内存 |
| 审计 | 只记录动作、状态、耗时和异常类型等最小化信息 |

## 5. 健康知识库

- 管理员 JWT 鉴权后才能上传、预览和删除。
- 限制文件类型与 5 MB 大小。
- 文档处理在事务中完成，避免半成品数据。
- 检索 SQL 和缓存键都包含用户边界，防止跨用户数据混用。

## 6. 管理后台

| 能力 | 当前状态 |
| --- | --- |
| 管理员登录 | BCrypt 密码校验 + JWT |
| 用户和消息查看 | 仅管理员可访问 |
| 健康知识库管理 | 上传、查看、删除 |
| 普通用户通过 `userId` 登录 | 已移除 |
| 图片、文件、订单、票券后台 | 已移除 |

## 7. 明确移除的历史能力

旅游规划与订单、12306、B 站收藏夹、命理塔罗、通用搜索、热搜、二维码生成、图片生成、语音合成、通用文件助手、快递、菜谱和通用待办已不属于当前产品边界。

天气和地图只作为健康场景的支撑服务，例如季节健康提醒和附近药店，不作为独立 Agent 方向。
